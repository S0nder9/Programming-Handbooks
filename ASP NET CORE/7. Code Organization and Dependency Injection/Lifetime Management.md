# Lifetime Management (Время жизни сервисов)

При регистрации зависимости в контейнере DI необходимо указать **время жизни (Lifetime)** сервиса.

От этого зависит:

- сколько экземпляров объекта будет создано;
- как долго они будут существовать;
- будут ли они повторно использоваться.

В ASP.NET Core существует три основных времени жизни:

- **Transient**
- **Scoped**
- **Singleton**

---

# 1. Transient

```csharp
builder.Services.AddTransient<
    IEmployeesRepository,
    EmployeesRepository>();
```

## Как работает

Каждый раз, когда контейнеру нужен объект, он создаёт **новый экземпляр**.

Даже в рамках одного HTTP-запроса при двух обращениях будут созданы два разных объекта.

```
HTTP Request
      │
      ├──► new EmployeesRepository()
      │
      └──► new EmployeesRepository()
```

---

## Пример

```csharp
app.MapGet("/", (
    IEmployeesRepository repo1,
    IEmployeesRepository repo2) =>
{
    Console.WriteLine(
        ReferenceEquals(repo1, repo2));
});
```

Результат:

```
False
```

`repo1` и `repo2` — разные объекты.

---

## Когда использовать

Подходит для сервисов, которые:

- не хранят состояние;
- лёгкие в создании;
- используются независимо друг от друга.

Например:

- калькуляторы;
- валидаторы;
- генераторы;
- мапперы.

---

# 2. Scoped

```csharp
builder.Services.AddScoped<
    IEmployeesRepository,
    EmployeesRepository>();
```

## Как работает

Во время одного HTTP-запроса создаётся **один экземпляр**.

Все зависимости внутри этого запроса используют один и тот же объект.

После завершения запроса объект уничтожается.

```
Request 1
    │
    ├──► EmployeesRepository
    └──► EmployeesRepository
         ▲
         │
    Один экземпляр

-----------------------

Request 2
    │
    ▼
Новый EmployeesRepository
```

---

## Пример

```csharp
app.MapGet("/", (
    IEmployeesRepository repo1,
    IEmployeesRepository repo2) =>
{
    Console.WriteLine(
        ReferenceEquals(repo1, repo2));
});
```

Результат:

```
True
```

Но при следующем HTTP-запросе будет создан новый объект.

---

## Когда использовать

Это **наиболее распространённый Lifetime**.

Подходит практически для всех сервисов, работающих с запросом:

- репозитории;
- Unit of Work;
- сервисы бизнес-логики;
- `DbContext` (Entity Framework).

---

# 3. Singleton

```csharp
builder.Services.AddSingleton<
    IEmployeesRepository,
    EmployeesRepository>();
```

## Как работает

Контейнер создаёт объект **только один раз**.

Все запросы используют один и тот же экземпляр.

```
Application Start
        │
        ▼
EmployeesRepository
        ▲
        │
 ┌──────┼───────┐
 │      │       │
 ▼      ▼       ▼
Req1   Req2    Req3
```

Объект существует до завершения работы приложения.

---

## Пример

```csharp
app.MapGet("/", (
    IEmployeesRepository repo1,
    IEmployeesRepository repo2) =>
{
    Console.WriteLine(
        ReferenceEquals(repo1, repo2));
});
```

Результат:

```
True
```

И даже при следующем запросе будет использоваться тот же экземпляр.

---

## Когда использовать

Подходит для объектов, которые:

- дорого создавать;
- являются потокобезопасными (thread-safe);
- должны существовать в единственном экземпляре.

Например:

- кэш;
- конфигурация;
- логгер;
- фабрики;
- сервисы чтения настроек.

---

# Сравнение

| Lifetime | Когда создаётся | Когда уничтожается | Повторное использование |
|-----------|-----------------|--------------------|--------------------------|
| **Transient** | Каждый раз при запросе зависимости | Сразу после завершения использования (обычно после запроса) | ❌ Нет |
| **Scoped** | Один раз на HTTP-запрос | После завершения запроса | ✅ В пределах одного запроса |
| **Singleton** | Один раз за всё время работы приложения | При остановке приложения | ✅ Во всех запросах |

---

# Что выбрать?

Обычно используются следующие правила:

- **Transient** — для небольших сервисов без состояния.
- **Scoped** — для сервисов, связанных с обработкой HTTP-запроса (репозитории, `DbContext`, бизнес-логика).
- **Singleton** — для общих сервисов, которые можно безопасно разделять между всеми запросами.

В большинстве ASP.NET Core-приложений **Scoped** является наиболее часто используемым временем жизни.

---

# Важное ограничение

Нельзя внедрять сервис с меньшим временем жизни в сервис с большим.

Например:

```text
Singleton
    │
    ▼
Scoped
```

или

```text
Singleton
    │
    ▼
Transient
```

Это может привести к использованию уже уничтоженных объектов или некорректному состоянию.

Например, нельзя внедрить `DbContext` (Scoped) в Singleton-сервис, потому что `DbContext` создаётся заново для каждого запроса, а Singleton живёт всё время работы приложения.

---

# Итог

Выбор Lifetime определяет жизненный цикл объектов в приложении:

- **Transient** — новый экземпляр при каждом обращении.
- **Scoped** — один экземпляр на каждый HTTP-запрос.
- **Singleton** — один экземпляр на всё время работы приложения.

Правильный выбор времени жизни помогает избежать лишних затрат на создание объектов, проблем с памятью и ошибок, связанных с многопоточностью.
