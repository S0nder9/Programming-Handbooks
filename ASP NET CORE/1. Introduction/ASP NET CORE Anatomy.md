## ASP.NET Core Anatomy

ASP.NET Core обрабатывает каждый HTTP-запрос как последовательный pipeline (цепочку обработки), где каждый этап выполняет свою задачу.

---

## 1. Обработка запроса (Request Processing)

Когда приходит HTTP-запрос, он сначала попадает в веб-сервер и превращается в объект .NET — **HttpContext**.

Он содержит всю информацию о запросе и ответе:

- данные запроса (headers, body, query)
- информацию о пользователе
- данные ответа
- сервисы текущего запроса

Финальная точка обработки запроса называется:

- **Endpoint** — конечный обработчик запроса (Controller, Minimal API, Razor Pages)

---

## 2. Middleware Pipeline

Перед тем как запрос дойдет до endpoint, он проходит через цепочку компонентов — **middleware pipeline**.

Каждый middleware может:

- обработать запрос
- изменить его
- завершить обработку
- передать дальше по цепочке (`next`)

---

## Основные этапы pipeline

### 1. Routing (маршрутизация)

- Определяет, какой endpoint должен обработать запрос
- Сопоставляет URL с конкретным обработчиком

---

### 2. Authentication & Authorization

- **Authentication** — проверяет, кто пользователь (идентификация)
- **Authorization** — проверяет права доступа пользователя

---

### 3. Model Binding

- Преобразует данные HTTP-запроса в объекты .NET
- Примеры:
  - query string → параметры метода
  - route params → аргументы endpoint
  - JSON body → C# объект

---

### 4. Model Validation

- Проверяет корректность входных данных
- Использует атрибуты валидации:
  - `[Required]`
  - `[Range]`
  - `[StringLength]`

---

## 5. Application Layer!
Самый важный этап, в нем находится основная логика приложения, то есть то, что именно делает система после того, как запрос уже обработан инфраструктурой (middleware, routing и т.д.).
После прохождения middleware запрос попадает в слой приложения:

- **Controllers (MVC)**
- **Razor Pages**
- **Minimal APIs**

Здесь выполняется основная логика приложения.

---

## 6. Business Logic & Data Access

На этом этапе происходит:

- выполнение бизнес-логики
- работа с сервисами
- взаимодействие с базой данных (например, через **Entity Framework Core**)
- выполнение CRUD-операций

---

## 7. Формирование ответа

После обработки данных формируется HTTP-ответ:

- статус-код (200, 404, 500 и т.д.)
- headers
- body (JSON, HTML, текст)
