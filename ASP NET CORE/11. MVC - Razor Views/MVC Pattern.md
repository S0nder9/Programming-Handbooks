


**MVC (Model–View–Controller)** — это архитектурный шаблон, который разделяет приложение на три независимые части:

- **Model** — данные и бизнес-логика;
- **View** — пользовательский интерфейс;
- **Controller** — обработка запросов и управление взаимодействием между Model и View.

Главная цель MVC — **разделение ответственности (Separation of Concerns)**, благодаря чему код становится проще поддерживать, тестировать и расширять.

---

# Структура MVC

```
        HTTP Request
              │
              ▼
        +--------------+
        | Controller   |
        +--------------+
         │          │
         │          ▼
         │      +--------+
         │      | Model  |
         │      +--------+
         │          │
         ▼          │
      +---------------+
      |     View      |
      +---------------+
              │
              ▼
        HTTP Response
```

---

# Model

**Model** представляет данные приложения и бизнес-логику.

Он отвечает за:

- хранение данных;
- работу с базой данных;
- проверку данных (валидацию);
- выполнение бизнес-логики.

Пример:

```csharp
public class Employee
{
    public int Id { get; set; }

    public string Name { get; set; }

    public string Position { get; set; }

    public double Salary { get; set; }
}
```

Во многих проектах Model взаимодействует с репозиториями или сервисами:

```csharp
IEmployeeRepository
```

или

```csharp
EmployeeService
```

---

# View

**View** отвечает только за отображение данных пользователю.

В ASP.NET Core MVC представления обычно создаются с помощью **Razor** (`.cshtml`).

Например:

```csharp
public IActionResult Index()
{
    return View();
}
```

Файл:

```
Views/
    Employees/
        Index.cshtml
```

Внутри представления можно использовать модель:

```cshtml
@model Employee

<h1>@Model.Name</h1>
```

View не должна содержать сложную бизнес-логику — её задача только отображать данные.

---

# Controller

**Controller** принимает HTTP-запросы, вызывает необходимые модели или сервисы и возвращает ответ.

Пример:

```csharp
public class EmployeesController : Controller
{
    public IActionResult Details(int id)
    {
        var employee = repository.GetById(id);

        return View(employee);
    }
}
```

Контроллер:

1. получает запрос;
2. извлекает параметры;
3. обращается к модели или сервису;
4. выбирает представление;
5. возвращает ответ клиенту.

# Как работает MVC

Пусть пользователь открывает:

```
GET /employees/details/5
```

### Шаг 1

Запрос попадает в систему маршрутизации (**Routing**).

---

### Шаг 2

Routing определяет:

```
EmployeesController
```

и действие

```
Details(5)
```

---

### Шаг 3

Контроллер получает данные:

```csharp
var employee =
    repository.GetById(5);
```

---

### Шаг 4

Контроллер передаёт модель представлению:

```csharp
return View(employee);
```

---

### Шаг 5

View генерирует HTML:

```html
<h1>John</h1>
```

---

### Шаг 6

HTML отправляется пользователю.

# MVC и Web API

Если создаётся обычный сайт:

```
Controller
        │
        ▼
      View
        │
        ▼
      HTML
```

Если создаётся Web API:

```
Controller
        │
        ▼
      Model
        │
        ▼
      JSON
```

В этом случае вместо

```csharp
return View();
```

обычно используют

```csharp
return Ok(employee);
```

или

```csharp
return Json(employee);
```

# Преимущества MVC

- Чёткое разделение ответственности.
- Код легче поддерживать и расширять.
- Проще тестировать отдельные компоненты.
- Можно независимо изменять пользовательский интерфейс и бизнес-логику.
- Хорошо подходит для крупных проектов.

---

# Недостатки

- Более сложная структура по сравнению с Minimal API.
- Требует большего количества файлов и кода.
- Для небольших REST API может быть избыточным.

---

# Сравнение компонентов

| Компонент | Отвечает за |
|-----------|-------------|
| **Model** | Данные, бизнес-логика, работа с БД |
| **View** | Отображение данных пользователю (HTML) |
| **Controller** | Обработка HTTP-запросов, взаимодействие между Model и View |

---

# Итог

**MVC (Model–View–Controller)** — архитектурный шаблон, разделяющий приложение на три независимые части:

- **Model** хранит данные и реализует бизнес-логику;
- **View** отображает информацию пользователю;
- **Controller** принимает HTTP-запросы, взаимодействует с Model и выбирает, какой ответ вернуть (View, JSON, файл, редирект и т.д.).

Такое разделение делает приложение более структурированным, удобным для сопровождения и масштабирования.
